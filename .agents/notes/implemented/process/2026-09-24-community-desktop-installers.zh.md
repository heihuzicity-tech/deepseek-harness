# Agent Note: 社区桌面安装包

Status: implemented

[English](2026-09-24-community-desktop-installers.md) | 中文

## 问题

公开 fork 需要提供可下载的桌面安装包，但无法访问上游的 Apple Developer ID、公证凭据、Windows 签名令牌或更新基础设施。其应用代码必须保持官方源码。

## 决策

独立的 GitHub Actions 工作流在全新原生运行器上打包无需证书的社区安装包。辅助脚本位于 `.github/desktop`，复用上游准备流程和组装后的运行时检查。生成的临时准备脚本仅省略 Developer ID 签名；已入库的上游准备脚本保持完整。上游签名代码块发生变化时，准备流程会失败，直至完成审查。安装包只有通过打包后的运行时检查，包括 Host 启动与 Office 转换，才能上传。

[官方签名发布流水线](../architecture/2026-08-25-electron-desktop-packaging-and-updates.zh.md) 保持独立。社区产物带有不同的后缀且没有更新源，无法满足该流水线的发布完成条件。

## 考虑过的替代方案

**要求上游签名凭据**会阻止独立运营的 fork 构建安装包。macOS 临时签名与 Windows 未签名打包支持手动分发，同时明确放弃经验证的发布者身份。

**修改官方应用或打包脚本**会增加持续合并的负担，并削弱上游签名发布检查。独立构建辅助脚本保留这些检查，同时保持应用行为不变。

## 影响

fork 无需仓库机密即可获得可重复执行的原生构建。用户手动安装更新，可能需要操作系统批准。运行时检查验证归档完整性、原生依赖、Host 启动与 Office 转换；不能据此确认公证、交互式安装成功或真实模型连通性。上游打包流程变化后，需先审查辅助配置和生成的准备脚本，再发布下一次构建。
